# RO 单据工作台产品方案

## 1. 产品概述

`RO Document Workbench` 是面向 RO 订单业务的**单据工作台**。它把"准备数据"和"装配单据"合并成一个连续的视觉操作：用户在同一个工作空间里浏览 PO、补齐字段、看到四类单据（PI、PO、Invoice、PL）的实时预览，并在确认后导出 Excel。

工作台不是一个生成器，而是一个**数据-文档一体的工作空间**。打开工作台 = 打开一份业务工作，关闭工作台 = 工作完成或暂存。MVP 阶段聚焦"用户在工作台里独立完成业务"这一核心场景；Agent 协作能力作为后续扩展（参见 §16 后续路线）。

四类业务单据：

- `PI`：Proforma Invoice，形式发票
- `PO`：Purchase Order，采购订单
- `Invoice`：正式发票
- `PL`：Packing List，装箱单

需要明确的是：**本工具不生成业务编号**（包括发票号 `INV#`、工厂文件号 `FACTORY DOC NO.`、出厂日期等）。这些字段必须由业务人员在工作台里录入，工具只负责读取、校验、装配和呈现。

## 2. 背景与问题

当前流程主要依赖人工操作：

1. 打开 `RO DATA BASE.xlsx`。
2. 在 `PO record` 中筛选 PO 行。
3. 根据 `SAP Number` 从 `DATA BASE` 中查找产品描述、价格、包装、重量、尺寸和 CBM。
4. 将数据复制到 PI、PO、Invoice、Packing List 模板。
5. 人工检查合计金额、箱数、体积、发票号和文件号。
6. 另存为最终单据。

主要问题：

- **数据和文档割裂**：源数据在 Excel，文档也在 Excel，但中间靠人工搬运。任何一处改动都要重新搬一遍。
- **错误反馈晚**：缺字段往往在装完单据后才发现，要回头找源数据再来一遍。
- **重复劳动**：四类单据共用同一份数据，但每类都得手工填一遍。
- **无可见性**：没人能一眼看出"这批 PO 中哪些可以开票了"。
- **无可逆性**：上一次生成的单据如果有错，没法基于它快速修正——只能从零再做。

工作台形态的目标是**消灭"翻译"动作**：数据视图和文档视图是同一份事实的两种呈现，改任意一边，另一边即时更新。

## 3. 产品目标

### 3.1 体验目标

- **零学习曲线**：用过 Excel 的人 30 秒内理解用法。
- **5 秒导出**：从打开工作台到导出一个就绪 PO 的全套单据，5 秒内完成。
- **实时预览**：选中 PO 的瞬间，4 类单据预览即时出现。
- **错误源头解决**：缺字段在工作台里直接补，不需要回 Excel。
- **可逆**：任何改动可撤销，任何导出可回看历史版本。

### 3.2 集成目标

- **离线优先**：核心操作（浏览、编辑、预览、导出）100% 离线可用。部署形态为**本地启动器 + 浏览器**（参见 §7.2），双击启动、数据不出本机。
- **机器接口可达**：除工作台 UI 外，提供 CLI 作为命令行入口，便于开发期调试、自动化脚本和未来扩展（如 Agent 集成）。
- **架构可扩展**：核心装配逻辑封装在独立 Python 包中，工作台后端、CLI 都是薄壳。未来增加 Agent/MCP 等新接口时，只需新增壳层，不需改核心包（参见 §7）。

### 3.3 贸易链段

RO 业务存在多段贸易主体链路，同一个 PO 在链条里可能产生多张不同主体的 Invoice。`PO record` 中的三组发票金额列直接反映这条链：

```text
工厂  →  SK / YM  →  GS PTE  →  EMAX PTE  →  PF（最终客户）
            ↓ GS-SK/YM INV-*    ↓ EMAX-GS INV-*   ↓ PF-EMAX INV-*
```

工作台默认呈现"当前 PO 在所有链段下的所有单据"，用户可在贸易链图上切换或全选。合法的 `(seller, buyer)` 组合：

| seller | buyer | 价格列 | Invoice 列前缀 |
|---|---|---|---|
| SK / YM | GS PTE | `SK/YM USD FOB` | `GS-SK/YM INV-*` |
| GS PTE | EMAX PTE | `GS PTE FOB` | `EMAX-GS INV-*` |
| EMAX PTE | PF（最终客户） | `EMAX PTE` | `PF-EMAX INV-*` |

不在表中的组合视为非法。

## 4. 核心体验原则

工作台的所有交互设计围绕五条原则展开。任何与原则冲突的需求需明确取舍。

### 4.1 实时预览，不是最终生成

选中 PO 即出现预览。改任何字段，预览即时刷新。"导出"按钮不创造结果，只是**确认"我已经看到的东西"**。这条原则消除了"按下生成键的焦虑"。

### 4.2 直接操作，不是表单提交

每个决策都在"看见可选项"的状态下做出：

- 选 PO：从带状态色的列表里点选，不是输入框。
- 选月份：看到月度出货 bar chart，点要的那个月。
- 选链段：看到贸易链图，点其中一段。
- 多 INV# 选择：在预览旁直接列出候选并点选。

### 4.3 错误在源头解决

工具检测到 "INV# 为空" → 在预览里高亮空字段 → **用户在工作台里直接填** → 工具回写到 base 文件 → 预览即时更新。不再有"改 Excel 再回来"的循环。

### 4.4 双向溯源

- 点文档预览里任意单元格 → 高亮 base 文件中的源字段。
- 点 base 文件中任意字段 → 高亮所有用到它的文档位置。

这是建立工具信任最关键的能力。

### 4.5 可逆与历史

- 每次导出都有版本，可回看上次生成的单据是什么样子。
- 任何对 base 数据的修改可撤销。
- 导出后发现错误，可"基于上次导出修正字段并重新生成"，不需从零再做。

## 5. MVP 范围与不做范围

### 5.1 MVP 范围

- 单 base 文件 + 多 PO 浏览。
- 完整工作台 UI，覆盖 §4 五条原则。
- CLI 作为机器接口，复用同一核心包。
- GS、EMAX、SK、YM 四主体的全套模板和 mapping。
- 离线运行（本地启动器 + 浏览器，参见 §7.2）。

### 5.2 不做范围

#### 5.2.1 产品形态

- 不替代 Excel 作为业务源数据存储。
- 不做多用户协同编辑（同一个 base 文件不能多人同时改）。
- 不做权限审批流。
- 不接入 ERP/SAP 系统。
- 不做云端托管（MVP 仅本地）。
- 不做 Agent / MCP 集成（作为后续路线，参见 §16）。

#### 5.2.2 业务字段

- 不自动生成业务编号（INV#、FACTORY DOC NO.、出厂日期等）。
- 不处理税务/关务段（HS Code、原产地、税号等）。
- 不做单价改写（只读取 `DATA BASE` 已有价格）。

#### 5.2.3 货币

- **MVP 仅支持 USD**。

#### 5.2.4 调用形态

- 不做手动按行拆量。PI/PO 的数量来源固定为 `客户PO.Order Quantity`；Invoice/PL 的数量来源固定为指定 `invoice_month` 的月度出货数量。

## 6. 目标用户

| 用户 | 主要场景 |
|---|---|
| 跟单/单证人员 | 工作台主用户。日常浏览 PO、补字段、导出单据。 |
| 业务主管 | 用工作台的 PO 状态总览快速判断进度。 |
| 模板维护者 | 当业务方调整 Excel 模板时更新对应 YAML 映射。使用工作台的"模板预览"工具验证 mapping 正确性。 |
| 开发/维护人员 | 维护核心包、schema、校验规则。当业务规则变更时介入。 |

> 后续若引入 Agent/自动化集成（参见 §16 后续路线），将新增"Agent/自动化系统"作为机器调用方用户。

## 7. 产品形态架构

工作台和 CLI 共享同一个**核心装配引擎**，业务逻辑只写一次。

```text
┌─────────────────────────────────────────────────────────────┐
│  核心包 ro_generator                                          │
│  - schema / validator / resolver                             │
│  - document_model / template_mapping / renderer              │
│  - 双向溯源索引 / 公式回退 / 校验分级                            │
└──────────────────────────────────────────────────────────────┘
              ▲                          ▲
              │                          │
       ┌──────┴──────┐            ┌──────┴──────┐
       │     CLI     │            │ 工作台后端 API │
       │ ro-generate │            │             │
       └─────────────┘            └──────┬──────┘
                                         │
                                  ┌──────┴───────┐
                                  │  工作台前端 UI │
                                  │（浏览器渲染）   │
                                  └──────────────┘
```

### 7.1 架构纪律

- **业务规则只写在核心包里**。CLI、工作台后端、前端 UI 都是薄壳，不允许写业务判断、校验逻辑或装配逻辑。
- 工作台后端是核心包的**网络包装层**，只负责 HTTP/IPC 协议、session 管理、前端事件路由。
- 任何"路由处理器里的 if 业务条件"都是越界，应该重构进核心包。

> 这条纪律的意义在于**为后续扩展预留通路**：未来要增加 MCP server 或 Agent tools 时，只需在核心包之上再加一个薄壳，几乎零成本。如果业务逻辑漏到 UI 层或后端路由层，这种扩展就要做大动作。

### 7.2 部署形态

工作台采用**本地桌面启动器 + 浏览器**模式：用户双击应用图标启动启动器，启动器在本地拉起后端服务并自动打开系统默认浏览器到工作台 URL。所有数据和处理 100% 在用户机器上完成，不依赖任何云端服务。

```text
┌─────────────────────────────────────────────────────────┐
│  桌面启动器（PyInstaller 打包，单可执行文件）              │
│  - 拉起后端 server（监听 localhost 随机可用端口）          │
│  - 打开默认浏览器到 http://localhost:<port>               │
│  - 托盘图标：状态显示 / 退出                               │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  浏览器（用户系统默认）                                    │
│  - 工作台前端 UI                                          │
└─────────────────────────────────────────────────────────┘
```

#### 7.2.1 选择理由

| 候选 | 结论 |
|---|---|
| 纯 Web App（远程托管） | 与"离线优先"和"不做云端托管"冲突，排除。 |
| 本地 Web（手动启动 server + 浏览器访问） | 离线满足，但启动流程繁琐（终端、端口、URL），违反"零学习曲线"。 |
| 完整桌面 App（Electron / Tauri） | 体验最佳，但首次实现增量成本 3–6 周（打包、签名、公证、自动更新、原生集成），MVP 不必要。 |
| **本地启动器 + 浏览器（选定）** | 双击即用，离线满足，复用浏览器渲染能力。在本地 Web 之上的增量成本约 3–5 天。 |

#### 7.2.2 技术栈

- **启动器**：Python + PyInstaller 打包为单可执行文件（macOS `.app` / Windows `.exe`）。负责进程管理、端口分配、浏览器启动、托盘集成。
- **后端**：FastAPI（异步、自带 OpenAPI），监听 localhost 上启动时探测到的可用端口。
- **前端**：Vue 3 + TypeScript + Pinia（Vite 构建）。前端构建产物作为静态资源由后端 server 直接 serve，避免独立部署。
- **预览渲染**：后端生成结构化 JSON payload，前端渲染为 HTML table + CSS 样式文本。点击可溯源字段弹出 popover 显示数据来源。

#### 7.2.3 关键约束

- **端口分配**：启动时探测可用端口，不写死。
- **单实例**：第二次双击启动器时不重复拉起 server，而是把已有浏览器 tab 调到前台或新开一个。
- **优雅退出**：通过托盘菜单退出；关闭浏览器 tab 不停 server（用户可能只是临时关闭页面）。
- **签名要求**：macOS 需 Apple Developer ID 签名以避免 Gatekeeper 拦截；Windows 不强制签名，但建议签名以避免 SmartScreen 警告。
- **资源边界**：启动器只持有"启动 / 停止 / 状态"三种状态，所有业务逻辑都在后端，启动器本身不解析 Excel、不读 mapping。

#### 7.2.4 已知局限

- 浏览器文件系统权限受限：用户通过文件选择器指定 base 文件后，所有读写经后端中转，不直接访问磁盘任意路径。
- 不能注册自定义协议（如 `roworkbench://`），未来 Agent 集成若需要 deep link，需要升级到完整桌面 App。
- 安装包受 Python runtime 体积影响，预计 30–80 MB。
- 用户必须有可用的现代浏览器（Chrome / Edge / Safari / Firefox 任一）。

#### 7.2.5 后续升级路径

如未来出现下列需求，可平滑升级到 Electron / Tauri 等完整桌面 App：

- 需要 `roworkbench://` 自定义协议（典型场景：Agent deep link）。
- 需要原生菜单栏、文件关联、文件拖拽到应用图标启动等深度系统集成。
- 用户反馈"还要装浏览器"是体验障碍。

升级时**核心包、后端 API、前端 UI 完全复用**，仅替换启动器壳层。这条迁移成本可控（首次约 3–6 周），是"先 B+ 再 C"路径的核心价值。

## 8. 工作台设计

### 8.1 布局

两栏 + 三 tab 顺序工作流：

```text
┌──────────────────────────────────────────────────────────────┐
│  顶部栏：base 文件路径 │ 导出                                  │
├────────────┬─────────────────────────────────────────────────┤
│            │  数据检查 │ 单据预览 │ 导出确认                     │
│  PO 队列    │  ─────────────────────────────────────           │
│  （左侧栏） │  选中 tab 对应内容区                               │
│            │                                                 │
│  搜索、筛选  │  - 数据检查：PO 行表格 + inline 编辑 + 问题摘要     │
│  多选      │  - 单据预览：链段胶囊选择 + header/table 分区域     │
│  状态着色   │    渲染 + 悬停/点击看溯源 popover                   │
│            │  - 导出确认：勾选单据类型 → 下载                     │
├────────────┴─────────────────────────────────────────────────┤
│  底部栏：PO 状态 │ 阻断/警告数                                   │
└──────────────────────────────────────────────────────────────┘
```

> 实施中从早期三栏 IDE 布局改为 tab 顺序工作流，以降低首次使用的认知负荷。数据检查和单据预览不同屏——先在"数据检查"里确认数据完整，再切换"单据预览"查看效果。

### 8.2 PO 列表（左侧栏）

PO 队列，支持搜索、多选、按状态筛选。每个 PO 一行，按状态着色：

| 状态 | 颜色 | 含义 |
|---|---|---|
| `ready` | 绿 | 全部字段就绪，所选链段+月份的全套单据可立即导出。 |
| `partial` | 黄 | 部分单据可导出（如 PI/PO 就绪但 Invoice 缺 INV#）。 |
| `blocked` | 红 | 阻断错误（缺 SAP、SAP 不在 DATA BASE 等）。 |

### 8.3 PO 数据视图（"数据检查" tab）

类 Excel `<table>`，呈现选中 PO 的所有行（即 `PO record` 中该 PO 号下的全部行）。

关键能力：

- **inline 编辑**：双击单元格即可改值，回车提交，立刻刷新预览。
- **缺字段高亮**：必填字段为空时红框。
- **问题摘要条**：顶部显示阻断数、警告数、行数、链段信息。
- **公式回退提示**：`SUBTOTAL` 等公式列读到 None 时装配引擎现算，单元格显示橙色边框。

### 8.4 链段与 document type 选择器（"单据预览" tab 顶部）

**链段选择**：横向胶囊按钮显示三个链段（SK/YM → GS PTE → EMAX PTE），点击切换定价视角。

**单据类型切换**：PI / PO / Invoice / PL 四个标签，点击切换预览的单据类型。SK/YM 主体下 PO 按钮自动禁用。

### 8.5 文档预览（"单据预览" tab）

四类单据的实时预览。当前渲染策略：

- **结构化渲染**：后端将 `DocumentModel` 序列化为 JSON payload（含 `layout.top` / `layout.info` 区域、`column_labels`、`lines`、`totals`），前端按区域渲染为 HTML table + 样式化文本。不再通过 SheetJS 加载 xlsx 二进制。
- **悬停/点击溯源**：点击可溯源字段（如订单行 quantity、header 的 invoice_no）→ 弹出 popover 显示来源 sheet、字段名、行号、取值规则。
- **缺字段占位**：缺失字段显示 "需填: ..." 占位文本。

### 8.6 导出

顶部"导出"按钮：

- 默认导出当前预览中的全部单据，按 §12 命名规则输出到工作台数据目录的 `outputs/` 子目录。
- 下拉菜单可选 zip 打包、单文件、按链段分别打包等。
- 导出后弹出"打开输出目录 / 复制路径 / 重新打开预览"。

每次导出自动创建一个**版本快照**，保存导出参数、当时的 base 数据状态、生成的文件。可在版本历史里查看任意一次导出，并支持"基于此版本修正"。

### 8.7 历史与版本

顶部栏的"版本历史"打开右侧抽屉：

- 时间线列出所有导出版本，每条带 PO 号、链段、月份、文件数。
- 点击版本可：
  - 打开当时生成的文件。
  - 查看与当前数据的 diff（哪些字段后来改过）。
  - "基于此版本修正"——以该版本为起点，应用当前的修改并生成新版本。

### 8.8 模板预览工具（独立小工具）

模板维护者专用，独立于主工作台 tab：

- 上传 base 文件 + mapping YAML。
- 渲染"这次会写哪些单元格、值是什么"，不实际导出。
- 高亮 mapping 引用但模板里不存在的单元格、合并冲突、行起始位置错误。

## 9. 数据源说明

Base 文件包含三张必需 sheet：

| Sheet | 表头行 | 数据起始行 | 用途 |
|---|---|---|---|
| `DATA BASE` | 4 | 5 | 产品主数据，~248 行 × 28 列 |
| `PO record` | 4 | 5 | 订单和出货计算 |
| `客户PO` | 1 | 2 | SAP 客户订单数据，26 列，按 `Purchasing Document`（= PO 号）关联 |

### 9.1 `DATA BASE`

`DATA BASE` 是产品主数据表，约 248 条产品数据、28 个字段。表头在第 4 行，数据从第 5 行开始。

| 字段 | 含义 |
|---|---|
| `SAP` | SAP 物料号，产品唯一识别码。 |
| `Material Description` | 产品英文描述。 |
| `GS MODEL` | GS 型号或客户型号。 |
| `Category` | 产品类别：`1=combo`，`2=rod`，`3=reel`。 |
| `MOQ` | 最小起订量。**MVP 仅作信息字段读取，不参与校验。** |
| `FOB LT` | FOB 交期或生产周期。**MVP 仅作信息字段读取。** |
| `SK/YM ... FOB 2026` | SK/YM 主体下不同类别产品的 FOB 单价（USD）。 |
| `GS PTE ... FOB 2026` | GS PTE 主体下不同类别产品的 FOB 单价（USD）。 |
| `EMAX PTE ... FOB 2026` | EMAX PTE 主体下不同类别产品的 FOB 单价（USD）。 |
| `inner case value` | 内箱/内盒相关参数。 |
| `round value` | 外箱装箱数或取整参数。 |
| `N/W`, `G/W` | 净重、毛重。 |
| `L`, `W`, `H` | 外箱长、宽、高。 |
| `CBM` | 外箱体积。 |
| `包装` | 包装方式，例如 carton、box、bulk、clam。 |
| `品牌` | 品牌，例如 Quantum、Lew's。 |
| `RFID` | RFID 标记。**缺失时记为低严重度 warning。** |
| `主件编号` | combo 类产品的主件编号或关联编号。 |

### 9.2 `PO record`

`PO record` 是订单和出货计算表，通过 `SAP Number` 引用 `DATA BASE`。

| 字段组 | 字段 |
|---|---|
| 订单识别 | `SHIP TO`, `PO NO.`, `ITEM LINE#`, `SAP Number` |
| 产品信息 | `DESCRIPTION`, `CATEGORY`, `BRAND` |
| 数量与价格 | `FINALQTY`, `SK/YM USD FOB`, `GS PTE FOB`, `EMAX PTE`, `SUBTOTAL` |
| 日期 | `ORDER DATE (EMAIL)`, `PO DELIVERY DATE`, `FINAL CONFIRMED EX-FACTORY DATE`, `ETD ON BOARD` |
| 装箱 | `CTNS`, `N/W`, `G/W`, `L`, `W`, `H`, `TOTAL CBM`, `外箱` |
| 发票信息 | `INV#`, `FACTORY DOC NO.` |
| 月度出货 | `2601` 到 `2612`, `BALANCE QTY` |
| 月度发票金额 | `GS-SK/YM INV-*`, `EMAX-GS INV-*`, `PF-EMAX INV-*` |

## 10. 业务规则

### 10.1 类别与单价

类别定义：

- `Category = 1` → combo
- `Category = 2` → rod
- `Category = 3` → reel

单价由 `(seller, buyer, category)` 三个维度决定：

| 链段 `(seller → buyer)` | combo 单价列 | rod 单价列 | reel 单价列 |
|---|---|---|---|
| `SK / YM → GS PTE` | `SK/YM combo FOB 2026` | `SK/YM rod FOB 2026` | `SK/YM reel FOB 2026` |
| `GS PTE → EMAX PTE` | `GS PTE combo FOB 2026` | `GS PTE rod FOB 2026` | `GS PTE reel FOB 2026` |
| `EMAX PTE → PF` | `EMAX PTE combo FOB 2026` | `EMAX PTE rod FOB 2026` | `EMAX PTE reel FOB 2026` |

> 列名为示例，实际以 `RO DATA BASE.xlsx` 表头为准，schema 阶段做规范化匹配。

### 10.2 计算公式

- `SUBTOTAL = quantity * unit_price`
- `CTNS = quantity / 外箱`
- `TOTAL CBM = L * W * H / 1000000 * CTNS`
- `BALANCE QTY = FINALQTY - 各月出货数量合计`
- `2601` 到 `2612` 表示 2026 年 1 月到 12 月的出货月份。

### 10.3 数量来源

- **PI / PO**：使用 `客户PO.Order Quantity`。
- **Invoice / PL**：使用 `invoice_month` 对应的月度出货数量。该月某行出货为 0 时，该行不出现在 Invoice/PL 中。
- 任何场景下都不对单行做手工拆量。

### 10.4 公式回退

`PO record` 中 `SUBTOTAL`、`CTNS`、`TOTAL CBM` 通常来自 Excel 公式。当 `data_only` 读取得到 `None`（说明保存该文件的 Excel 程序未缓存公式结果），装配引擎按 §10.2 公式现算，并在工作台数据视图中以橙色边框标记，预览中同样有溯源标注。

## 11. 校验体系

### 11.1 三类校验输出

| 类型 | 含义 | 工作台呈现 |
|---|---|---|
| `blocking_errors` | 阻断装配，必须修复。 | PO 行红色、阻断字段红框、底部状态栏显示数量。 |
| `warnings` | 可装配但需复核。带 `severity: high \| low`。 | high 黄色提示条；low 折叠在小图标里。 |
| `missing_inputs` | 信息不足，需用户选择。 | 在预览旁直接列候选项点选。 |

### 11.2 警告严重度

| severity | 触发场景 |
|---|---|
| `high` | PO 行数超出模板默认行区域；SAP 在 `DATA BASE` 找到但价格为 0；PL 字段部分缺失但仍能装配；公式回退现算。 |
| `low` | `RFID`、`SUB-CATEGORY`、可选日期字段为空。 |

### 11.3 信息缺口与候选

| missing_input | 触发条件 | 候选来源 |
|---|---|---|
| `seller` / `buyer` | 用户未在工作台明确选定链段，且 PO 数据可对应多个合法链段 | 合法链段（§3.3） |
| `invoice_month` | 请求 Invoice/PL 但未指定月份，且 PO 在多个月份都有出货 | 该 PO 有出货数量的月份代码 |
| `invoice_no` | 同一 `(po, invoice_month)` 对应多个不同 `INV#` | 候选发票号 |

工作台 UI 在缺信息时直接呈现候选，不需要弹窗提交。核心包内部以下列结构表达 `options`，CLI 输出和未来的机器接口都共享这套 schema：

```json
{
  "missing_inputs": ["invoice_month"],
  "options": {
    "invoice_month": [
      { "value": "2601", "label": "2026 年 1 月（出货 240 件）" },
      { "value": "2602", "label": "2026 年 2 月（出货 80 件）" }
    ]
  }
}
```

## 12. 输出与文件交付

### 12.1 文件命名规则

| 单据类型 | 命名模板 |
|---|---|
| PI | `<SELLER>-RO-PI-<PO>.xlsx` |
| PO | `<SELLER>-RO-PO-<PO>.xlsx` |
| Invoice | `<SELLER>-RO-INVOICE-<PO>-<INVOICE_NO>.xlsx` |
| PL | `<SELLER>-RO-PL-<PO>-<INVOICE_NO>.xlsx` |

> 实施选择用 `<INVOICE_NO>` 而非月份代码，因为同一月份可能对应多张不同发票号的单据，用发票号更精确。

### 12.2 重复导出策略

工作台默认行为：每次导出**写入 `outputs/<导出版本号>/` 子目录**，避免覆盖。版本号 = `YYYYMMDD-HHMMSS`。用户在版本历史里能看到所有版本。

CLI 保留显式 `on_conflict` 选项：

- `overwrite`（默认）：覆盖同名文件。
- `rename`：追加 UTC 时间戳。
- `abort`：目标文件存在时返回 error。

### 12.3 文件交付

工作台导出后文件直接落到本地数据目录，UI 提供"打开输出目录 / 复制路径"。CLI 输出文件路径为绝对路径，便于脚本进一步处理。

## 13. 模板策略

### 13.1 模板矩阵

| 主体 | PI | PO | Invoice | PL |
|---|:-:|:-:|:-:|:-:|
| GS | ✅ | ✅ | ✅ | ✅ |
| EMAX | ✅ | ✅ | ✅ | ✅ |
| SK | ✅ | ❌ | ✅ | ✅ |
| YM | ✅ | ❌ | ✅ | ✅ |

SK / YM 没有 PO 模板。在工作台里，SK/YM 链段下的 PO 文档预览栏显示"该主体不出 PO"占位，导出按钮自动禁用 PO 项。

### 13.2 模板与 mapping 同步

模板维护者每次修改 Excel 模板后必须更新对应 YAML 映射。工作台加载 mapping 时校验：

- mapping 中引用的所有单元格地址在模板里确实存在且可写。
- `lines.style_source_row` 指向的样式来源存在，并应指向真实明细样式行。
- `totals.*` 引用的合计单元格在模板中真实存在。
- 如声明 `table_header_row`，该行必须位于 `start_row` 上方，用于显式保护真实表格表头。

任一校验失败时工作台标识具体的 mapping 字段，§8.8 模板预览工具提供视觉化诊断。mapping 文件中要求 `template_version` 字段，用于排查"模板换了但 mapping 没改"。

### 13.3 模板目录可配

工作台启动时支持 `--templates-dir` 指定模板目录，不强制内嵌。这让模板维护可以与产品发布解耦——业务方可以在不更新工具版本的前提下迭代模板。

## 14. 成功指标

### 14.1 体验指标

- 黄金 PO `4500030844`：工作台从打开到导出全套单据 **< 5 秒**（含预览渲染）。
- 缺字段在工作台内补全 → 预览刷新 < 200 ms。
- 用户首次使用工作台到完成第一次导出 < 5 分钟（无需培训）。
- 模板维护者用模板预览工具诊断一次 mapping 错误 < 2 分钟。

### 14.2 正确性指标

- 装配结果与人工模板**逐字段一致**（值层面）：产品行、数量、单价、金额、合计、箱数、N/W、G/W、CBM、INV#、FACTORY DOC NO.。
- 模板样式保持完整：合并单元格未被破坏、打印区域可正常打印、列宽与行高与模板一致。回归测试通过 openpyxl 重读输出文件验证。
- 三类校验输出在已知样例中行为正确：缺 SAP 阻断、多月出货触发候选、`RFID` 缺失只产生 low warning。

### 14.3 接口稳定性指标

- CLI 退出码、命令行参数 schema 在 MVP 发布后保持向后兼容。
- 核心包 Python API 保持稳定，便于工作台后端和未来扩展接口（如 Agent/MCP，参见 §16 后续路线）共用。

### 14.4 可维护性指标

- 模板维护者**只通过修改 YAML 映射**就能适配单元格位置调整，无需改 Python 代码。
- 新增一个主体（如未来 `XX PTE`）的全套四类模板，从拷贝目录到完成回归测试目标 **< 1 工作日**。

## 15. 风险与应对

| 风险 | 应对 |
|---|---|
| 不同主体模板字段位置不一致 | 每个模板独立的 YAML 映射；§13.2 mapping 校验。 |
| `.xls` 模板处不稳定 | MVP 前手工一次性转换为 `.xlsx`；原 `.xls` 留底；业务方今后只在 `.xlsx` 上修改。 |
| 部分字段需要人工录入 | 工作台直接呈现缺字段并允许 inline 补全，不自动编造。 |
| PO 行数超过模板默认区域 | 自动插入行并复制样式；§11.2 触发 high warning 提示用户复核打印分页。 |
| Excel 公式在不同环境不重算 | 装配优先写最终值；读取时若 `data_only` 拿到 None 按 §10.4 现算并标记。 |
| 模板漂移：业务方改 Excel 但未改 YAML | mapping 加载阶段校验；mapping 中要求 `template_version`；模板预览工具视觉化诊断。 |
| openpyxl 处理合并单元格、打印区域、行高时隐性损坏 | Phase 0 spike 验证；回归测试用 openpyxl 重读输出文件，断言合并范围、列宽、打印区域不变。 |
| 多币种需求出现 | MVP 锁定 USD（§5.2.3）；扩展时通过版本升级处理。 |
| base 文件含敏感数据，无法作为 fixture 提交 | 编写合成 fixture 生成脚本；真实文件仅本地手工 QA。 |
| 工作台前端预览与最终导出不一致 | 预览和导出共用同一份 DocumentModel 和 mapping；最终导出由 openpyxl 渲染以确保样式保真。 |
| 工作台后端 API 设计若耦合 UI 或前端框架，未来扩展 Agent/MCP 成本将显著升高 | 业务逻辑禁止写入路由层和前端层；后端 API 按"无界面也可调用"标准设计；CLI 与工作台后端共用核心包入口，作为这条架构纪律的活体校验（参见 §7.1）。 |
| PyInstaller 打包在跨平台或 Apple Silicon 上行为不一致 | Phase 0 启动器 spike 同时覆盖 macOS（含 Apple Silicon 和 Intel）与 Windows；CI 上构建测试同步覆盖。 |
| macOS Gatekeeper / Windows SmartScreen 拦截未签名应用 | 申请 Apple Developer ID 并在 CI 中接入 codesign + notarytool；Windows 端建议申请代码签名证书，至少在 README 中说明首次启动绕过方法。 |
| 用户系统默认浏览器异常或被禁用 | 启动失败时提供回退提示（如显示 URL 让用户手动复制），并写入启动日志便于排查。 |
| 浏览器 tab 被关闭后用户以为程序退出，但 server 仍在运行 | 托盘图标常驻显示当前状态；提供"退出"菜单项；启动器一段时间无活动连接后可选择性进入 idle 提示。 |
| 同一台机器上多次双击启动器导致端口/数据冲突 | 启动器实现单实例锁；第二次双击时把已有浏览器 tab 调到前台或新开一个，不重复拉起 server（参见 §7.2.3）。 |

## 16. 发布计划

### Phase 0：可行性 spike

在投入完整开发前先验证四个高风险假设：

- **模板样式保留 spike**：openpyxl 对一个真实 Invoice 模板做"读取 → 写入 → 插入 1 行 → 复制样式 → 保存"，重读后断言合并单元格、打印区域、列宽、行高未损坏。
- **预览渲染 spike**：选定预览组件（如 SheetJS / Luckysheet 等），验证能加载渲染后的 `.xlsx` 并保持视觉与导出一致。
- **启动器打包 spike**：用 PyInstaller 把"FastAPI server + 自动开浏览器 + 托盘退出"打包为单可执行文件，验证在 macOS（含 Apple Silicon 和 Intel）和 Windows 上能双击启动、端口探测正确、退出干净。同时确认 macOS 签名/公证流程与 Windows SmartScreen 处理方案。
- **fixture 数据策略决策**：与团队确认真实 base 文件是否可入库；若不能，定义合成 fixture 生成脚本的最小覆盖范围。

只有全部 spike 通过、fixture 策略确定后才进入 Phase 1。

### Phase 1：核心包 + CLI

- 解析 `RO DATA BASE.xlsx`、schema 校验、resolver、document model。
- 完成第一个单据类型（建议 Invoice）的渲染。
- 提供最小 CLI 用于命令行装配。
- 双向溯源索引随核心包构建。

### Phase 2：四类单据 + 多主体模板

- 增加 PI、PO、PL 渲染器。
- 完成 GS、EMAX、SK、YM 模板矩阵（§13.1）。
- 与人工单据逐字段比对达到 §14.2 一致性。
- 模板预览工具的命令行版本。

### Phase 3：工作台 MVP

- FastAPI 后端 + 前端单页应用（前端框架在 Phase 0 spike 后选定）。
- PyInstaller 启动器：单可执行文件，双击启动、自动开浏览器、托盘退出（参见 §7.2）。
- §8 工作台布局：PO 列表、数据视图、链段图、月份选择器、文档预览栏。
- inline 编辑、缺字段高亮、双向溯源、撤销/重做、版本历史。
- 模板预览工具的图形化版本。
- macOS 与 Windows 安装包构建与签名流程接入 CI。

### Phase 4：加固

- 扩充回归测试：combo/rod/reel 单价选择、跨月度切片、多 INV#、SAP 缺失阻断、SK 主体 PO 模板阻断、模板样式回归。
- 性能优化：大 base 文件（500+ PO）下 PO 列表与预览刷新延迟。
- 模板版本管理。

### 后续路线（不在 MVP 范围）

以下能力作为 MVP 之后的潜在扩展，按真实需求驱动单独立项，不进入当前发布计划：

- **Agent / MCP 集成**：在工作台之上增加 Hermes Agent 协作能力。考虑过的形态包括 Hermes 调度 + 工作台 deep link、工作台内召唤 AI 的 power tool 模式、Agent 后台守护（异常检测、进度提醒、模式学习）。架构上通过新增 MCP server 壳层接入核心包（参见 §7.1）。
- **批量自动化**：一次处理多个 PO，可能由 Agent 触发也可能由 CLI 脚本驱动。
- **PDF 导出**：在 Excel 之外提供 PDF 版本。
- **云端协作**：多用户协同、版本共享、远程访问。
