# 单据模板字段取值规则汇总

本文档按字段名称汇总 14 类业务单据/Sheet 的取值来源，用于快速对比同一字段在不同单据中的来源差异。当前代码以 12 个 `.xlsx` workbook 和 18 份 YAML mapping 实现这些版式。

## 说明

| 说明项 | 内容 |
| --- | --- |
| 统计口径 | 统计 14 类业务单据/Sheet；共享 workbook 的 Sheet 仍分别统计。源 base 文件不作为单据模板。 |
| 忽略文件 | 忽略 .~ 开头的 Excel 临时锁文件。 |
| 核对依据 | 结合模板单元格中的中文来源注释、公式和 模板取数逻辑说明.md；固定值以当前模板实际内容为准。 |
| 价格选择规则 | PI/PO/PL/CI 仍从 DATA BASE 按 Category 取 FOB 列。RO Invoice 从当前发票对应的 PO record 行取按主体聚合单价：SK/YM 共用 K列 `GS-SK/YM USD FOB`，GS PTE 用 M列 `EMAX-GS PTE FOB`，EMAX PTE 用 O列 `EMAX PTE`。 |
| 内部单据类型 | 核心包使用 PI / PO / INVOICE / PL / CI / RO_PL；CI/RO_PL 是 SK/YM 的 RO 版商业发票/装箱单。 |
| 数量选择规则 | PI/PO 使用客户PO N列 Order Quantity；INVOICE/PL/CI/RO_PL 使用 PO record AM列 SHIP QTY。 |
| SK/YM 主体过滤规则 | SK/YM 层按 PO record 的 CATEGORY 判断主体：1/2 属于 YM，3 属于 SK。工作台或 CLI 已明确选择 seller=SK/YM 时，只预览和导出该主体对应行，不自动把另一主体拆成额外文件。GS PTE 与 EMAX PTE 不使用此规则。 |
| 空白含义 | 矩阵表中空白表示该单据没有对应字段, 或模板未出现该字段。 |
| 最近核对 | 2026-08-19 |

## 关键规则摘要

- PI/PO/PL/CI 价格列通常按 `DATA BASE` 的 `Category` 选择：`1=combo`、`2=rod`、`3=reel`；YM 主体 PI 例外，固定取 `DATA BASE` G列 `GS-SK/YM COMBO FOB 2026`。
- RO Invoice 单价取当前发票对应 `PO record` 行：SK/YM 共用 K列 `GS-SK/YM USD FOB`，GS PTE 用 M列 `EMAX-GS PTE FOB`，EMAX PTE 用 O列 `EMAX PTE`。
- SK/YM 层的预览与导出按已选主体过滤 `PO record.CATEGORY`：`1/2 -> YM`，`3 -> SK`。页面选择 SK 或 YM 后，只处理该主体对应行。
- `G/H/I` 对应 `GS-SK/YM FOB`；`J/K/L` 对应 `EMAX-GS PTE FOB`；`M/N/O` 对应 `EMAX PTE FOB`。
- `PI/PO` 数量通常取 `客户PO N列 Order Quantity`；`INVOICE/PL/CI/RO_PL` 数量通常取 `PO record AM列 SHIP QTY`。
- `RO DATA BASE & PO record template.xlsx` 是数据源文件，不计入单据模板。
- 结构化预览的单据标题和出具方抬头按 mapping 的 `preview_content.template_fields` 从当前 Excel 模板读取；header 字段标签从对应值单元格所在行读取，区域位置由 `preview_content.layout` 声明。前端不另写 SK、YM、GS PTE 或 EMAX PTE 的抬头文案。
- 结构化预览的明细列名直接读取当前 Excel 模板的 `table_header_row`；mapping 的 `preview_content.column_labels` 只声明列和顺序。多行表头按行换行显示，模板空白子列不补写推测文案。

## PF Customer Profile 增量规则

PF 使用独立的 Customer Profile，不复用 RO 的 sheet 名、字段位置或客户差异规则。当前基准文件为 `Template PF/PO RECORD 2026.xlsx`，工作区配置时应选择该 `.xlsx` 文件，而不是仅选择目录。

### 数据源与订单生命周期

| 逻辑数据 | PF 实际 Sheet | 表头/数据起始 | 用途 |
| --- | --- | --- | --- |
| 产品主数据 | `DATA BASE TEMPLATE` | 第 2 行 / 第 3 行 | SAP、Category、MOQ、`round value`、包装数据和各贸易链价格 |
| 已维护订单/出货 | `PO RECORD 26` | 第 1 行 / 第 2 行 | 已进入出货流程的订单、发票号、月度出货数量和实际出厂日期 |
| 客户原始订单 | `new PO template` | 第 1 行 / 第 2 行 | 新 PO、规格、订单数量、客户要求出厂日期 |

- 新订单即使尚未同步到 `PO RECORD 26`，也会从 `new PO template` 出现在 PO 视图，并可装配 PI/PO。
- 这类仅存在于客户 PO 的行是只读投影；没有真实 `PO RECORD 26` 行号时，页面不允许误进入 PO record 编辑。
- Invoice/PL 仍要求订单已进入 `PO RECORD 26`，并具有发票号和对应出货月份数量。

### 分类、数量与价格

- PF 的 Category 文本映射为：`Combo -> 1`、`Single Rod -> 2`、`Single Reel -> 3`。
- PI/PO 数量取 `new PO template.Order Quantity`。
- Invoice/PL 数量按 `INV#` 中的 `YYMM` 选择 `PO RECORD 26` 的 `2601`～`2612` 数字月份列；无法唯一确定时才回退到 `SHIP QTY`。
- PF 当前采用 `20260612-NEW PO` 价格版本：SK/YM → GS 取 `GS-SK/YM ...`，GS → EMAX 取 `EMAX-GS ... 留下3%`，EMAX → PF 取 `PF-EMAX ... EFFECTIVE AS OF JUN/12/26-NEW PO`。PI/PO 与 Invoice/PL 的**主单价**都读各链段的 COMBO 列；DATA BASE 把 Single Rod / Single Reel 的卖价写在 COMBO 列，ROD/REEL 列是 Combo 的组件价，只用于 Invoice 成本拆分。
- PF 发票号直接使用 `INV#` 原值，不追加 RO Profile 的 `-P` 后缀。

### MOQ 与整箱提醒

检查对象是同一 PO 内按 SAP（规格）汇总后的客户订单数量，而不是逐行孤立判断：

| 检查 | 数据源 | 触发条件 | 输出 |
| --- | --- | --- | --- |
| MOQ | `DATA BASE TEMPLATE.MOQ` | 汇总订单数量 `< MOQ` | 高优先级、非阻断提醒 `MOQ_NOT_MET` |
| 整箱 | `DATA BASE TEMPLATE.round value` | 汇总订单数量不是整箱数的整数倍 | 高优先级、非阻断提醒 `FULL_CARTON_NOT_MET`，同时显示余数 |

提醒会携带 `new PO template` 的来源行和 `Order Quantity` 字段，便于定位。缺少有效 MOQ/整箱基数时不推断、不编造规则；提醒本身不阻断预览与导出，由业务人员确认是否调整订单。

### 出厂日期与 PL 装箱计算

- PF Invoice/PL 的出厂日期优先取 `PO RECORD 26.ACTUAL EX FACTORY`，为空时回退订单出厂日期。
- PF 月度出货箱数为 `当月出货数量 / DATA BASE TEMPLATE.round value`。
- PF GS/EMAX 装箱单首列 `CTN# Fr/To` 按本单明细箱数累计：第一行从 1 起到该行箱数，后续行接上一行的截止箱号。箱数须大于 0；非整数向上取整后再编号。缺箱数或箱数为 0 时该行留空，并且后续行不再累计，避免从 1 重新编造。
- `PO RECORD 26` 的 N/W、G/W 是原订单总量，生成月度 PL 时按“月度出货箱数 / 原订单箱数”同比例缩放。DATA BASE 的 N/W、G/W 是单箱重量；PO 总量缺失，或订单箱数缺失/为 0 时，用单箱重量 × 本月出货箱数，不能把单箱值再当总量去除以订单箱数。
- TOTAL CBM 优先按 `L × W × H / 1,000,000 × 月度出货箱数` 计算。
